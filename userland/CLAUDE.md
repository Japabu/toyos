# Userland

Root `CLAUDE.md` is always loaded and binds here; this file is userland's own rules.

**Daemons** — compositor, netd, soundd, sshd. Compositor, netd and soundd each claim a device from the kernel, map its buffers into their own memory, and serve clients over IPC; sshd claims no device and reaches the network through netd. Crash a daemon, the kernel is fine. **soundd drives both sound cards from userland, and the kernel keeps only the addresses**: on HDA it enumerates the codecs, chooses the output and configures the path; on virtio-sound it queries the stream, sets the format and publishes each period. Both reach the device through a positive register allow-list and never an address — the descriptor tables and the buffer descriptor list are the kernel's, built once at bind, so what a driver names is an index into a ring it maps (`specs/plans/hda-driver-plan.md` §4.1.6, §6.7). **virtio is not legacy and is not going away**: it is the right guest interface, and the better-behaved of the two backends today. **sshd is built into the image and started by nobody** — opt-in via `/bin/sshd &`: it listens on every interface, authenticates against `/home/root/.ssh/authorized_keys`, public keys only, an entry carrying options authorizes nothing, and a file that names no usable key makes it exit rather than hold a port it can never accept on.

**IPC** — a server is endowed an acceptor and a client a connector (`toyos::port`, names resolved through the namespace `/bin/init` built); accept and connect, no listen, no registry. Pipes are shared-memory ring buffers whose 2 MiB page is allocated on first use — `pipe::create` cannot fail, and a queued connection nobody has answered costs no memory. **A server never blocks on a client**: accept and the first frame are two events, a frame is buffered until whole before anything acts on it, and a write is one `try_send` whose refusal drops the peer by name. `ipc::recv_header`/`recv_payload`/`send` on a peer's fd is a client deciding when the server runs again, and **so is a blocking read or write of a pipe the client owns**. init, the compositor, netd and every surface host use `ipc::FrameRx`; soundd carries its own equivalent; filepicker uses neither and blocks on a silent client — `specs/issues/design-debt/filepicker-blocks-on-a-silent-client.md`.

**Display** — **the compositor decides nothing it cannot decide on the host.** Rects, damage, layout, hit testing, Z-order, input routing and the compose plan are `toyos-desktop/`, pure and host-tested; `userland/compositor/` is devices, fds, shared memory and the panel. A `Rect` is half-open corners, not origin-and-extent. **Nothing composes against the scanout**, the compositor included: it composes the whole desktop into one screen of RAM and blits damage rects — reads from the scanout miss every cache, so `window::Screen` is the mapping with no read path and `Framebuffer` means a surface in RAM. **Damage is a bounded list, never one bounding box**, and **`MSG_PRESENT` carries a `window::Rect`**, clamped to the window rather than believed. **Every mapping states its memory type** (`paging::CachePolicy`, no default): the scanout is write-combining, everything else defers to firmware's MTRR, which is PAT entry 0. `arch::pat` programs entry 4 to WC on every CPU, because the reset table has no WC entry at all; no MTRR is programmed — SDM Vol. 3A Table 11-7 gives WC for a WC PAT entry under every MTRR type. WC is weakly ordered, so `Screen::blit` and the panic console end with an `sfence` or the last partial buffer stays off the panel; QEMU's framebuffer is host RAM, so only the decision is testable (`metal_sim_scanout_wc`). **A damage cache needs one operation that distrusts it** — `ESC[2J` is that operation, and a `clear` that skips cells it already believes blank cannot clean a screen something else drew on. **A panel is not obliged to be a whole number of glyph rows tall** — the T14's 1080 is not — and the strip below the last cell row belongs to whoever owns the screen.

**A diagnostic line is several `write`s, and the kernel's log goes into the gaps.** The console and the log ring are one stream, so the unit of interleaving is a syscall — and `eprintln!` is one syscall per format fragment (stderr is unbuffered by design) while `println!` is two. Where the two writers are *correlated* the interleave is systematic, not bad luck. soundd, init and netd each carry a `say!` that puts a whole line in one `write_all`; the rest of `userland/`'s `eprintln!` sites do not, `compositor: ready` and `terminal: ready` among them (`specs/issues/diagnostics/serial-console-has-no-line-atomicity.md`).

## Input, from the userland side

Userland's half of the boundary root `CLAUDE.md` states. **A surface** owns a screen, a keyboard and one translator — the compositor's windows, `/bin/terminal`, `/bin/console` — and events flow *down* the tree: the compositor forwards whole transitions to the focused window and translates nothing, and a child wanting transitions rather than bytes asks its host over `toyos::surface`, which is **a port its host made and put in the namespace it spawned the child with** — one per terminal, one per console, reached under the name `surface` in every namespace that has one. Nothing outside that subtree can name it. While a grab is held the surface stops translating **and stops advancing its translator** — `Window::press` is called by whoever wants characters and by nobody else. Layout is a file (`surface::LAYOUT_CONFIG`) and the notification carries no name: it says the file moved and every translator re-reads it, so none can hold an opinion that disagrees with it.

## POSIX

The kernel ABI and SDK are Rust-native and capability-shaped. POSIX compatibility, where it is needed to run ecosystem software, belongs in a **userspace** compatibility layer (`userland/libc` — ToyOS's own code, not a fork) with explicitly relaxed rules. That layer may be ugly; the kernel may not.
