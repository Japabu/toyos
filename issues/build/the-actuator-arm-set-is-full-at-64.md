# `kernel/src/actuator.rs`'s arm set holds exactly 64 actuators and there is no 65th

`ARMED` is an `AtomicU64` and an actuator's bit is its index in `NAMES`
(`bit_of`), so the declaration list has room for `u64::BITS` names and no more.
`const _: () = assert!(NAMES.len() <= u64::BITS as usize, "more actuators than
bits in the arm set")` is the guard, and it is a compile error rather than a
silent aliasing — which is right, and is also the whole of the problem.

Measured 2026-08-22: **64 declared**, counted off the `actuators! { … }` body.
The set is exactly full. The next actuator anybody needs does not compile:

    error[E0080]: evaluation panicked: more actuators than bits in the arm set
       --> src/actuator.rs:837:5
    error[E0080]: evaluation panicked: attempt to shift left with overflow
       --> src/actuator.rs:812:20   (inside `bit_of`)

Both fire, and the second is the one that would have been dangerous if the
first were not there: `1 << 64` on a `u64`.

**How it was met.** The batch that threaded `BlockError::BudgetExpired` from
the driver to `/bin/logd` (2026-08-22) needed one arm — a SYNCHRONIZE CACHE
refused on the caller's operation budget rather than on anything the device
did, which is the exact state
`issues/boot-media/fsync-on-log-returns-other-under-a-loaded-host.md`
reproduced once in 73 full 12-wide suites and which no host-side option
stages: `usb-slow-device` is 2 ms per bulk completion against a 2 s bound
(three orders of magnitude, measured), `rerror`/`werror` fail the drive rather
than delaying it, and `block::OPERATION` is host wall clock. The arm was
written, refused to compile, and was removed rather than paid for by widening
the set inside somebody else's task. The end-to-end guest arm for that change
is therefore missing: the mint is gated by `cache_eviction`'s
`nvme-gate: … budget=true` and `usb_storage_gate`'s `usb-gate: … budget=true`,
the mapping by `toyos-fat32`'s host tests, and the decision by `logd::policy`'s
— but no single guest run carries a budget-expired flush all the way to logd's
retry line.

**What it is not.** Not "too many actuators". Every one of the 64 carries the
comment `actuator.rs`'s own header demands — why the state under it cannot be
staged from the host side — and nothing on the list is obviously spare. The
bound is the representation, not the appetite.

Closing it: `ARMED` becomes something wider than one word. `AtomicU128` does
not exist, so it is an array of `AtomicU64` with `bit_of` answering `(word,
bit)`, or a `[AtomicU64; N]` behind the same accessor shape — the accessors are
generated by the `actuators!` macro and every call site is `pub fn name() ->
bool`, so nothing outside this file changes. The `IMPLIES` resolution and the
duplicate-name `const _` both go through `bit_of` and follow it.
