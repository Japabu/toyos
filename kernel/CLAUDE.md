# Kernel

Root `CLAUDE.md` is always loaded and binds here; this file is the kernel's own rules. Every syscall is implemented in `kernel/src/arch/syscall.rs`.

## Subsystems

**Memory** (`kernel/src/mm/`) — shared memory across processes; a single heap allocation is bounded by `mm::MAX_HEAP_ALLOC`, one 2 MiB page minus its guard. `mmap`'s `prot` is enforced: no `WRITE` is a read-only PDE and `MmapProt::NONE` maps nothing. Kernel stacks that are heap get an unmapped page below them (`paging::guard_4k`). **An address userland chose is bounded at the primitive, never at the call site**: `AddressSpace::translate` refuses anything outside the user half, and a typed value is copied in or out only if the whole of it fits the one 2 MiB page a translation answers for; `UserAddr::checked` is the constructor for a number that crossed the syscall boundary, `UserAddr::new` for one the kernel computed; the arithmetic is `mm/user_span.rs`, host-tested in `kernel-span/`. The bounds live on the same primitives (`MAX_USER_STR` and kin), and **SMAP stays enabled 100% — no `stac`/`clac` anywhere**. **Nothing hands out a reference to user memory** — a bulk buffer is a `UserBytes`/`UserBytesMut` window with `read_at`/`write_at` and no way back to a slice, because a `&[u8]` over a page userland can rewrite carries `noalias` into LLVM. **A TLB shootdown is acknowledged**: `arch::tlb::shootdown` returns when every online CPU has flushed, never when the ICR is written, so unmap-then-free is sound — `mm::Unmapped<T>` is the type whose `Drop` shoots down and then frees, and `paging::map_mmio` covers the memory-type half of the same hazard. Every waiter also serves, answering before it asks, because `IF` is clear for the whole of every syscall (`MSR_FMASK`, nothing sets it before `sysretq`). The protocol is `kernel/src/shootdown.rs`, modelled in `kernel-loom`.

**Locking** — `kernel/src/sync.rs`'s `Lock` is a ticket spinlock that disables preemption for as long as it is held. There is no parking and no sleeping lock; what that costs on the disk path is the last caveat below.

**Processes** (`kernel/src/process.rs`, loading in `kernel/src/loader/`) — dlopen/dlsym for shared libraries. **A process is a `ProcessObject` a handle names, and there is no parent anywhere in the kernel**: `SYS_SPAWN` answers with a handle, the exit code is published onto the object once by whichever of exit, kill or panic recovery claimed the teardown, and everything holding a handle may read it for ever after — no zombie state exists and no exit can be missed. `SYS_PROCESS_OPEN` is the one place a pid becomes authority; it needs `Rights::MANAGE` on a `SysCap`, of which the kernel mints exactly one.

**Objects and handles** — `kernel/src/object/`. **A `HandleEntry` owns what it names and its count is what releases it**: `close`, exit and kill match on no resource kind, and a new kind is one row in `kobject!`. **`handle_count` is not the Arc count, and that is load-bearing** — EOF and dead-peer detection ride the handle count, and an internal `Arc` clone must not look like a live peer. A row's `deferred`/`immediate` decides locks, not stacks: a `deferred` hook runs from the zero-handle queue with nothing held, and a `deferred` container may hold an `immediate` object, so the drain has a task's stack. **A device claim is the one object admitting a single handle** — created without `Rights::DUP`, so exclusivity is the type's. **`BadHandle`, `Stale` and `WrongType` end the caller** (`HandleError::refuse`, exit 139); `Rights` and a full table do not. The exception is `SYS_NAMESPACE_BUILD`'s added connector: a `provides` name is a connector somebody else made — a trust boundary — so a wrong type there answers a word rather than ending the receiver. The kill needs the process's own lock, so no `HandleError` may be answered under one — `Refusal` is the carrier that gets it out, and `TableFull` is a separate type so the object layer, which installs under that lock, provably cannot reach the kill.

**Scheduling** — the core is `toyos-sched/`, a sans-IO state machine with its own simulator and invariants (`specs/scheduler-core-spec.md` is the design); the kernel drives it from `kernel/src/sched/`. `drain_irqs` at the top of every scheduler pass is where drivers get their turn, and housekeeping runs before `pass()`. **A one-shot arm has a floor, and `apic::OneShot` is the only thing that reaches the register**: the Ring 0 timer stub reloads the last count in assembly, so a count that does not outlast the interrupt it schedules is a CPU that retires nothing ever again — reachable from Ring 3 by a deadline already past. **QEMU cannot stage that and a green suite is not its verdict**: TCG retires a whole translation block per interrupt.

**Filesystem** (`kernel/src/vfs.rs` and the adapters beside it) — VFS with mount points: initrd, tmpfs, bcachefs on NVMe (`/home`), FAT32 (`/boot`, `/log`). **The kernel never formats a disk it was not given, and a failed mount is not consent** — a disk it cannot positively identify as ours is never written to. The ESP is FAT32 by UEFI mandate and is untrusted input like any other disk. **A mount's extent is the adapter's invariant, not the filesystem's to be trusted about**: clamp at the kernel boundary whatever the driver promises. A mount is named for its role, never its format. **Every mount states whether userland may change it** (`vfs::UserAccess`, no default): `/boot` says no — the modifying syscalls ask `Vfs::user_may_modify` and answer `PermissionDenied`, because a writable boot volume is an unbootable machine — and `/log` stays writable. **An operation that fails must not have destroyed what it was asked to replace, nor kept what it took**: write and insert first, free last, and give back every run a failed allocation loop reserved. **A backing is revoked, not kept alive, when its file goes**: the blocks are the next file's the moment the entry is gone, so a stale read must fail rather than serve them, and every backing for a name reads through one shared `FileBlocks`.

**Boot device identity** — the kernel is *given* its partitions by the bootloader, never asked to find any; selecting on a partition's *type*, or "the first one of the right format", is the prohibited shape. Every image has two: the ESP, and a Microsoft-Basic-Data FAT32 labelled `TOYOS-LOG` mounted at `/log` — its own partition because macOS never auto-mounts an EFI-typed one. `log_file` writes one file per boot there, named for the wall clock; `MAX_LOG_FILES` of them, oldest deleted first. **The RTC is read exactly once per boot** (`clock::init_wall`): FAT mtimes, the log filename and both clock syscalls are all that one reading plus the monotonic clock, and a machine whose RTC will not answer says why and writes `unknown-NN.log` rather than inventing 1970. The zone is firmware's (`EFI_TIME::TimeZone` via `KernelArgs`), because the CMOS carries none. The log partition's GUID reaches the kernel in `KernelArgs` off the ESP's `\toyos\log.guid`; a stick without it is a refusal by name, never a fallback.

**Storage** — `block::BlockDevice` is the one device interface, in whole 4 KiB blocks, and **the whole channel is fallible with nothing inventing a value in the middle**: `BlockDevice`, `FileBacking::read_page`, `bcachefs::BlockIO` and `vfs::FileSystem` all answer `Result` (`close_file` alone returns unit; `file_cache::read_page` answers `block::BlockError`), a failed read is never a page of zeros, and the file cache refuses a partial write into an unreadable page rather than merging it back over the file. `BlockIOExt` attaches the block number, so no implementation can name a block its caller did not ask for. `SyscallError::Io` is the only word for a device that did not do it — `NotFound` means the name is not there and nothing else may say so, which is why `open` with `CREATE` acts on `NotFound` alone. **A device's own numbers are untrusted** — checked, and the device refused by name, never truncated to fit; where a controller and a device each count one transfer, the smaller answer is the one a caller may read. **An optional command's refusal is an answer, not a device failure.** **A transfer the driver stopped waiting for is not a transfer that is over**: Bulk-Only Reset Recovery quiesces both endpoints before it says a word to the device (`Owed` carries that order), and `scsi` re-issues the command — a recovery restores the transport, not the transfer. **An error path that logs is an error path that produces work for the thing that failed**, so a log sink's own failures disable it rather than logging. **A disk's number is issued once, machine-wide, and never moves or comes back** — a number derived from a position in a list renumbers every disk when an earlier controller gains one, under mounts that hold it for life.

**Input** — the kernel's half of the boundary root `CLAUDE.md` states. Modifiers stay kernel-derived because the mask is the union across every keyboard. One held-set and one button-merge for the whole machine; the event queues are bounded (`MAX_QUEUED_EVENTS`, drop-oldest) and discarded when the device changes hands. Pointer sources are numbered where they bind, never by an index a device supplies, and given back on unplug — `mouse::unbind` is the only thing that frees one. USB HID and PS/2 both feed it in HID usage codes; wire decoding is `toyos-ps2/`. **A byte a decoder is still holding is not a byte that decoded to nothing.** The i8042's counter line repeats *only* when the pin has asserted since the last one, so its silence is evidence that no interrupt arrived, not that the driver stopped looking.

**USB hotplug** — the driver splits: `kernel/src/drivers/xhci/` owns the device; decisions are pure in `toyos-xhci/`, which has its own simulator. A device plugged in after boot enumerates and one pulled is torn down, off the Port Status Change Event through a per-port state machine stepped from `poll_if_pending`. **`drain_irqs` is its only legitimate caller**: a syscall that reaches it makes that thread the driver's engine. **Nothing on that path may wait** — it is the top of every scheduler pass, and the 100 ms debounce (USB 2.0 §7.1.7.3) or a root port's 55 ms reset would empty the audio pipeline on every plug; teardown and endpoint recovery are therefore submit-and-return against one outstanding operation per controller (`toyos_xhci::{job,recovery}`), and enumeration's blocking `configure` (`xhci/wait/boot.rs`) is the one caller left that blocks there. **CCS is a level, CSC is the edge** — only CSC shows a replug that happened between two looks, and it is reaped through the ordinary teardown before the port is treated as connected. A refused device holds its pool block until its port goes too.

**PCI** — drivers select from an enumerated list, so whether one takes the first match or all of them is visible at the call site; a first-match helper hides that choice. **Interrupts are armed in one place**: `PciDevice::enable_msix`/`enable_msi` over `toyos-pci`'s decode of the two capability structures; the fallback *policy* stays at the call site and differs per driver. `MSIX_ENTRY` is the one table entry this kernel programs, and a virtio device is told that number too.

## Faults, and the state a transition owns

**Every exception vector Intel names for 64-bit mode has a gate** — a vector without one is not a fault but a #DF and a halted machine. `idt_vectors!` declares the number, the stub's error-code form (SDM Vol. 3A Table 6-1) and the dispatch arm as one row, so no two can disagree: Ring 3 kills the process and names it, Ring 0 panics, #DF and #MC are aborts that halt either way. A Ring 0 panic that belongs to one task recovers — the task is poisoned and reaped with exit code −1, the CPU survives; a fatal panic halts and paints. Gate: `fault_gates` (`specs/issues/isolation/` holds its surviving arms).

**A transition out of Ring 3 that can reach another task saves and restores the *whole* user machine state, and a task that has never been in Ring 3 starts from a *declared* one** — `specs/user-machine-state.md`. `arch/entry.rs`'s `save_user_state!`/`restore_user_state!` is the one bracket on every transition path (the declared image lives in `arch/fpu.rs`), so "saved some of it" is not expressible. `FXSAVE64` is *complete* because `CR4.OSXSAVE` is set nowhere, and **enabling any XCR0 component means moving to XSAVE in the same commit** — the build stops on a reservation that did not grow. `IdtEntry` takes `Ring3Entry` or `Ring0Entry` and nothing else, and the build refuses a kernel target reporting `sse`, because the bracket is sound only while Ring 0 is soft-float. Gate: `fpu_isolation`, with a `fpu-save-nothing` negative control that must fail.

## Diagnostics on the panel

**A backtrace is named from the binary's own file**: `loader::symbols::read_backtrace_table` reads `.symtab`/`.strtab` off whatever backs the executable, so a program run from a disk reports like one run from the initrd; `SymbolTable` resolves with no allocation and no lock because the fault and panic handlers call it; `MAX_SYMBOL_BYTES` is 16 MiB, and a binary past it gets bare addresses, never a failed spawn. **There is no DWARF anywhere** — `toyos-ld` drops every debug section — so a frame carries a name and never a line number. Gate: `disk_backtrace`.

**On-screen panic console** (`kernel/src/drivers/panic_console/`) — fatal panics paint the log-ring tail as an 8x16 text grid on the GOP framebuffer; recovering panics never paint; the six boot phase boundaries repaint so a wedge shows the last phase reached. Armed before `serial::init`, takes no lock of any kind. A report longer than the screen is paged on a 3 s deadline; PageUp/PageDown steer it (polled off the i8042 once every CPU is halted), and the first key retires the deadline for good. The screen tests decode the screendump against the same `font8x16.bin` the kernel blits (`cargo run -- --regen-font` regenerates it); they are the only tests that read pixels (`specs/device-test-strategy.md`).

**Ctrl+Alt+D — the blocked-task dump** (`kernel/src/sched/dump.rs`) — what to press on a machine that stopped without panicking. **Pressing it destroys the evidence it reports on**: the request reschedules every CPU, so a machine frozen on an unfired deadline reports `0 overdue` — capture `info registers -a` over QMP *first*. Machine-wide and process-named: each CPU prints its own tasks from `drain_irqs`, and one that misses the 250 ms budget is asked by NMI, which `IF` cannot mask, so the report tells a spin from a lost kick from a wedge below the interrupt layer, and names the `rip`. The process table supplies every thread's name and published state — the only place a task no CPU was ever given appears. The verdict is the last line (overdue / absurd / unheld / never ran) and degrades field by field rather than withdrawing. It paints the panel and stays there: `request` brackets the log with two `log_ring::Mark`s so one report is painted, `[page n/m]` on it is a static footer, and `panic_console::hold_report` re-paints it from `drain_irqs` for 15 s on evidence, never on a timer, so a stopped machine pays one paint. **A USB keyboard summons it too** — `keyboard::handle_key` is the one production path for every keyboard and the hook is inside it — so plugging one into a frozen machine separates a dead i8042 from a dead machine. Gates: `blocked_dump`, `screen_blocked_dump`, `dump_nmi_probe`.

## Caveats that bite every agent

- **Anything added to the idle loop is an audio change** — housekeeping runs before `pass()`, so a woken CPU is late by what it costs. On a machine with nothing to run the idle loop does not run at all, so a diagnostic placed there reports nothing exactly when it is needed.
- **No disk wait in this kernel can park, and the driver is not why.** At the moment a transfer is waited for, the CPU is four ticket spinlocks deep — `log_file::SINK`, `vfs::VFS`, `fat32_adapter::VOLUMES`, `xhci::XHCI` — each disabling preemption for its whole life. `specs/plans/blocking-io-plan.md` is the wave; `specs/issues/audio/disk-wait-pins-a-cpu.md` the entry.
