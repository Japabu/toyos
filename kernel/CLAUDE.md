# Kernel

Loads when you read a file under `kernel/`. The rules that bind every agent — including *fail-fast is for kernel bugs, not untrusted input* and *the kernel must never crash from userland* — are in the root `CLAUDE.md`, which is always loaded.

## Subsystems

**Memory** — 2MB pages only. Demand paging. Shared memory across processes. **`mmap`'s `prot` is enforced**: no `WRITE` is a read-only PDE and `MmapProt::NONE` maps nothing, so a libc guard page faults. Kernel stacks that are heap get an unmapped page below them (`paging::guard_4k`); the per-CPU idle stack was the instance. **An address userland chose is bounded at the primitive, never at the call site**: `AddressSpace::translate` refuses anything outside the user half — a user PML4 shallow-copies the kernel's, so a kernel address used to translate to a writable kernel pointer — and a typed value is copied in/out only if the whole of it fits the one 2 MiB page a translation answers for. `UserAddr::checked` is the constructor for a number that crossed the syscall boundary, `UserAddr::new` for one the kernel computed. `mm/user_span.rs` is that arithmetic, host-tested in `kernel-span/`. **Nothing hands out a reference to user memory at all** — a bulk buffer is a `UserBytes`/`UserBytesMut` window with `read_at`/`write_at`, no `Deref` and no way back to a slice, threaded down to whichever leaf owns the kernel side of the copy: a `&[u8]` over a page userland can rewrite carries `noalias` into LLVM, which is what made every read-once-and-validate rule unenforceable. **A TLB shootdown is acknowledged**: `arch::tlb::shootdown` returns when every online CPU has flushed, never when the ICR is written, so unmap-then-free is sound — `mm::Unmapped<T>` is the type whose `Drop` shoots down and then frees, and `paging::map_mmio` exists because a memory-type change on a boot-map leaf is the same hazard. It waits with nothing held only because a CPU that cannot take the interrupt *serves* anyway — `Lock::lock`'s spin, and **the wait itself, which answers before it asks**. `IF` is clear for the whole of every syscall (`MSR_FMASK` masks it and nothing sets it again before `sysretq`), so what a target could be spinning on uninterruptibly cannot be enumerated once and stay true, and a wait that did not answer deadlocked two concurrent unmaps outright. The protocol is `kernel/src/shootdown.rs`, modelled in `kernel-loom`.

**Processes** — PIE binaries. Spawn-based. Full SMP. dlopen/dlsym for shared libraries. **A process is a `ProcessObject` a handle names, and there is no parent anywhere in the kernel**: `SYS_SPAWN` answers with a handle, the exit code is published onto the object once by whichever of exit, kill or panic recovery claimed the teardown, and everything holding a handle may read it for ever after — so there is no zombie, no reap, no adoption and no window in which an exit is missed. `SYS_PROCESS_OPEN` is the one place a pid becomes authority and it needs `Rights::MANAGE` on a `SysCap`, of which the kernel mints exactly one, for `/bin/init`.

**Objects and handles** — `kernel/src/object/`. **A `HandleEntry` owns what it names and its count is what releases it**, so `close`, exit and kill all match on no resource kind and a new kind is one row in `kobject!`. A row says `deferred` or `immediate`, and it decides locks and not stacks: a `deferred` hook runs from the zero-handle queue with nothing held, and where a *destructor* runs it cannot say — a `deferred` container may hold an `immediate` object, so the drain has a task's stack. **A device claim is the one object admitting a single handle** — it is created without `Rights::DUP`, so exclusivity is the type's rather than a check in `dup`. **`BadHandle`, `Stale` and `WrongType` end the caller** (`HandleError::refuse`, exit 139) and `Rights` and a full table do not — **except `SYS_NAMESPACE_BUILD`'s added connector, the one handle argument that routinely crossed a trust boundary**: a `provides` name is a connector somebody else made, so a wrong type there answers a word rather than ending whoever received it. The kill needs the process's own lock, so **no `HandleError` may be answered under one** — `Refusal` is the carrier that gets it out, and `TableFull` is a separate type so the object layer, which installs under that lock, provably cannot reach the kill.

**Scheduling** — Efficient, event-driven, fair-share. Per-CPU run queues. Must scale to 128+ cores without excessive overhead. **A one-shot arm has a floor, and `apic::OneShot` is the only thing that reaches the register**: the Ring 0 timer stub reloads the last count in assembly, so a count that does not outlast the interrupt it schedules is not a late tick but a CPU that retires nothing ever again — reachable from Ring 3 by a deadline already past, and it took cpu0 off the T14 on eight boots of eight (#156, closed). **QEMU cannot stage that and a green suite is not its verdict**: TCG retires a whole translation block per interrupt, so `short_sleep_livelock` passes on the tree that has the defect and says so in its own doc.

**Filesystem** — VFS with mount points. Initrd, tmpfs, NVMe, USB. **The kernel never formats a disk it was not given, and a failed mount is not consent** — a disk it cannot positively identify as ours is never written to. The ESP is FAT32 by UEFI mandate rather than by legacy, and is treated as untrusted input like any other disk. **A mount's extent is the adapter's invariant, not the filesystem's to be trusted about**: clamp at the kernel boundary whatever the driver promises. A mount is named for its role, never its format — naming it after its format is one step from selecting it by its format. **Every mount states whether userland may change it** (`vfs::UserAccess`, no default) and `/boot` says no: six syscalls ask `Vfs::user_may_modify` and answer `PermissionDenied`, because a process that can write the volume firmware reads the machine out of can make it unbootable. `/log` is still writable, this boot's log file included. **An operation that fails must not have destroyed what it was asked to replace, nor kept what it took**: write and insert first, free last, and give back every run a failed allocation loop reserved — `bcachefs`'s create, delete, rename and metadata paths all had this backwards. **A backing is revoked, not kept alive, when its file goes**: the blocks are the next file's the moment the entry is gone, so a stale read must fail rather than serve them, and every backing for a name reads through one shared `FileBlocks`.

**Boot device identity** — the kernel is *given* its partitions by the bootloader, never asked to find any. Selecting on a partition's *type*, or on "the first one of the right format", is the defect this exists to make unrepresentable. Every image has two: the ESP, and a Microsoft-Basic-Data FAT32 labelled `TOYOS-LOG` mounted at `/log`, where `log_file` writes **one file per boot named for the wall clock** (`2033-03-07-091426.log`; `MAX_LOG_FILES` of them, oldest deleted first and named in the log when it goes) — its own partition because macOS never auto-mounts an EFI-typed one, so the log was unreadable on the machine the owner reads it on. **The RTC is read exactly once per boot** (`clock::init_wall`), and FAT mtimes, that filename and both clock syscalls are all that one reading plus the monotonic clock; a machine whose RTC will not answer says why and writes `unknown-NN.log` rather than inventing 1970. The zone is firmware's (`EFI_TIME::TimeZone` via `KernelArgs`, `Localtime = UTC - TimeZone`), because the CMOS carries none and a Windows dual-boot keeps local time there. The image build mints its GUID, writes it to `\toyos\log.guid` on the ESP, and the bootloader carries it in `KernelArgs`; a stick without it is a refusal by name, never a fallback.

**Storage** — `block::BlockDevice` is the one device interface, in whole 4 KiB blocks, and **every method is fallible**: a failed read must not be indistinguishable from data. NVMe and USB mass storage implement it, which is how a machine that boots off a stick can read the stick. **A device's own numbers are untrusted** — checked, and the device refused by name, never truncated to fit; where a controller and a device each count one transfer, the smaller answer is the one a caller may read. **An optional command's refusal is an answer, not a device failure.** **A transfer the driver stopped waiting for is not a transfer that is over** — it is still the controller's to run and still the device's to answer, so Bulk-Only Reset Recovery takes both endpoints off their transfers before it says a word to the device (`Owed` carries that order into `reset_the_device`'s arguments), and `scsi` re-issues the command, because a recovery restores the transport and says nothing about what was on it. Backwards it cost a write per fault and was invisible here: whether the device's late answer undoes the reset is a race a KVM guest wins every run and a TCG one loses every run. And **an error path that logs is an error path that produces work for the thing that failed**, so a log sink's own failures disable it rather than logging. **`FileBacking::read_page` is fallible for the same reason** — a page the device would not give back is not a page of zeros, so the file cache refuses a partial write into one rather than merging and flushing it back over the file. **`bcachefs::BlockIO` is fallible too**, so the channel runs device → page cache → filesystem → syscall with nothing inventing a value in the middle; `BlockIOExt` attaches the block number, so no implementation can name a block its caller did not ask for. **`vfs::FileSystem` closes that chain and `file_cache::read_page` with it**: every method answers `Result<_, SyscallError>`, and `SyscallError::Io` is the only word for a device that did not do it — `NotFound` means the name is not there and nothing else may say so, which is why `open` with `CREATE` acts on `NotFound` alone.

**Input** — the kernel's half of the boundary root `CLAUDE.md` states. Modifiers stay kernel-derived because the mask is the union across every keyboard. One held-set and one button-merge for the whole machine, both bounded (`MAX_QUEUED_EVENTS`, drop-oldest) and discarded when the device changes hands. Pointer sources are numbered where they bind, never by an index a device supplies, and given back on unplug — `mouse::unbind` is the only thing that frees one and it clears the buttons first. USB HID and PS/2 both feed it in HID usage codes; wire decoding is `toyos-ps2/`. **A byte a decoder is still holding is not a byte that decoded to nothing** — conflating them made two thirds of a healthy pointer stream read as a desync and cost a field investigation. The i8042's counter line repeats *only* when the pin has asserted since the last one, so its silence is evidence that no interrupt arrived, not that the driver stopped looking.

**USB hotplug** — a device plugged in after boot enumerates and one pulled is torn down, off the Port Status Change Event through a per-port state machine stepped from `poll_if_pending`. **`drain_irqs` is its only legitimate caller**: a syscall that reaches it makes that thread the driver's engine — a read of the mouse fd did, and froze the T14's desktop for seconds. **Nothing on that path may wait**, which is the rule its debounce and its port reset already obey: it is the top of every scheduler pass, and 100 ms of USB 2.0 §7.1.7.3 or a T14 root port's 55 ms would empty the audio pipeline on every plug. Teardown and endpoint recovery are therefore submit-and-return against **one outstanding operation per controller** (`toyos_xhci::{job,recovery}`); a completion is matched by its **Command TRB address**, never by being first, and is *recorded* where it is read, because that drain runs inside somebody else's wait. `device::configure` is the one caller left that blocks there. **CCS is a level, CSC is the edge** — only CSC shows a replug that happened between two looks, and it is reaped through the ordinary teardown before the port is treated as connected. A transfer error on a port that has gone belongs to the disconnect, not to recovery, and an outstanding recovery is *cancelled* by it rather than waited out. Teardown order — input source, Disable Slot, pool block — is not a preference, and a **refused** device holds its block until its port goes too, or two bad sticks cost the machine every disk after them. **A disk's number is issued once, machine-wide, and never moves or comes back**: derived from a position in a list it renumbered every disk the moment an earlier controller gained one, under mounts that hold it for life.

**PCI** — drivers select from an enumerated list, so whether one takes the first match or all of them is visible at the call site. A first-match helper hides that choice, which is how a machine with two identical controllers ends up with one driven. **Interrupts are armed in one place**: `PciDevice::enable_msix`/`enable_msi` over `toyos-pci`'s decode of the two capability structures, so a new driver calls it rather than writing the fourth copy. The *policy* stays at the call site and differs — an xHC falls back to MSI, a virtio device refuses itself and the machine boots without it. `MSIX_ENTRY` is the one table entry this kernel programs, and a virtio device is told that number too.

## Faults, and the state a transition owns

**Kernel must never crash from userland.** A buggy userland process must not be able to bring down the kernel. But if the kernel itself has a bug, it must crash loudly so we can fix it and harden. **Every exception vector Intel names for 64-bit mode has a gate** — a vector without one is not a fault but a #DF and a halted machine, which is what a userland `div` by zero was. `idt_vectors!` declares the number, the stub's error-code form (SDM Vol. 3A Table 6-1) and the dispatch arm as one row, so no two can disagree: Ring 3 kills the process and names it, Ring 0 panics, #DF and #MC are aborts that halt either way. Gate: `fault_gates`, whose surviving arms print the status word saying why (`specs/issues/isolation/`, which also has the trap flag a process can still hang itself with).

**A transition out of Ring 3 that can reach another task saves and restores the *whole* user machine state, and a task that has never been in Ring 3 starts from a *declared* one** — `specs/user-machine-state.md`. `arch/entry.rs`'s `save_user_state!`/`restore_user_state!` is the one bracket and the only text in the kernel naming an FP instruction, so "saved some of it" is not expressible. `FXSAVE64` is *complete* because `CR4.OSXSAVE` is set nowhere, and **enabling any XCR0 component means moving to XSAVE in the same commit**: `UserFpState`'s size and alignment reach the assembly as `const` operands, so every reservation grows with the type or the build stops. It was eight partial copies — two entries, *every* exception vector including #PF and the shootdown IPI, saved nothing at all, and a pending x87 exception left on a CPU killed the next unrelated process at the `FLDCW` every binary's unwinder runs on every panic. `IdtEntry` takes `Ring3Entry` or `Ring0Entry` and nothing else, and `src/build.rs` refuses a kernel target reporting `sse`, because the bracket is sound only while Ring 0 is soft-float. Gate: `fpu_isolation`, three arms against a `fpu-save-nothing` kernel that must fail all of them. Cost, TCG only: **+123 cycles on `SYS_CLOCK`, 870→993, six interleaved pairs.**

## Diagnostics on the panel

**A backtrace is named from the binary's own file.** `loader::symbols::read_backtrace_table` reads `.symtab` and `.strtab` off whatever backs the executable into contiguous 2 MiB pages the process owns, so a program run from a disk gets the same report as one run from the initrd — `FileBacking::memory_ptr` is gone, and with it the one thing the initrd was load-bearing for. `SymbolTable` still resolves by raw-pointer scan with no allocation and no lock, because the fault handler and the panic handler call it. `MAX_SYMBOL_BYTES` is 16 MiB and a binary past it gets bare addresses and a log line, never a failed spawn. **There is no DWARF anywhere** — `toyos-ld` drops every debug section — so a frame can carry a name and never a line number. Gate: `disk_backtrace`.

**On-screen panic console** (`kernel/src/drivers/panic_console/`) — fatal panics paint the log-ring tail as an 8x16 text grid on the GOP framebuffer; recovering panics never paint; the six boot phase boundaries repaint so a wedge shows the last phase reached. Armed before `serial::init`, takes no lock of any kind. A report longer than the screen is paged on a 3 s deadline, and **PageUp/PageDown steer it** — polled off the i8042 once every CPU is halted, so the machine you are photographing can be asked for a particular page. **The first key retires the deadline for good**: a reader who has taken the wheel is reading one page, and it must not move under him. `cargo test -- screen` decodes the screendump glyph-by-glyph against the same `font8x16.bin` the kernel blits; regenerate it with `cargo run -- --regen-font`. `screen_console_shell` and `screen_console_panic` join that family for `/bin/console`, decoding against the *console's* table from the same producer that fills the initrd — and the two tables not decoding each other is what stops either test passing on a screen the other painted. **These are the only tests that read pixels** — everything else asserts on console text, because a screenshot is a poor way to ask whether the right process came up.

**Ctrl+Alt+D — the blocked-task dump** (`kernel/src/sched/dump.rs`) — what to press on a machine that stopped without panicking, and what to ask the owner for. Machine-wide and process-named: a `CpuSched` is `!Sync`, so the asking CPU marks and kicks every sibling and each prints its own tasks from `drain_irqs` — **a CPU that misses the 250 ms budget is then asked by NMI, which `IF` cannot mask, so the report tells a spin from a lost kick from a wedge below the interrupt layer, and names the `rip`**. Two halves that cannot see each other: the CPUs give deadline, wait class and how long the park has lasted; the process table gives every thread's name and published state, the only place a task *no CPU was ever given* appears at all. The verdict is the last line (overdue / absurd / unheld / never ran), it degrades field by field rather than withdrawing, and it paints the panel — taking the screen, because the machine it is for has no serial port. **What reaches the panel is the report, and it stays there.** `request` brackets the log with two `log_ring::Mark`s so the console paints *one report* rather than the newest screenful of a ring every process writes into — a tail paginates the answer against a whole boot's logging, and `[page n/m]` on a Ctrl+Alt+D panel is a *static footer*, never a pager, because `page_forever` is reachable only from `halt_all_cpus`. And `panic_console::hold_report` puts the report back from `drain_irqs` for 15 s whenever the panel stops carrying it, because a compositor that is still composing does not know the kernel drew and overwrites it inside a frame. It repaints on evidence and never on a timer — 128 remembered pixels re-read every 20 ms — so a machine that has genuinely stopped pays one paint and no photograph catches a fill. **A USB keyboard summons it too** — `keyboard::handle_key` is the one production path for every keyboard and the hook is inside it — so plugging one into a frozen T14 separates a dead i8042 from a dead machine with no reflash. Gates: `blocked_dump`, `screen_blocked_dump`, `dump_nmi_probe`.
